# Прогон 10 длинных ТЗ

Дата прогона: 17 октября 2026. Модель `qwen3.8:27b`, окно сборки 12000 символов, пересечение окон 800. Связь с моделью не обрывалась: все 10 документов дошли до YAML. Ошибок схемы нет.

Документы: `probe/docs/wide-01-harbor.md` … `wide-10-clinic.md`. У каждого метода хвост с полями и кодами начинается после 13000 символов. Результаты: `out/probe/wide-*.yaml`.

## Что сборка уже делает верно

Эти случаи в плане не переписываются.

- Псевдоним слота пути не стал вторым параметром. В договоре аренды адрес `{contractId}`, в таблице рядом стоит `agreementId`, в YAML только `contractId`.
- Пример со старой версией не стал вторым вызовом. У торгов таблица `POST /auction/v2/lots/{lotId}/close`, пример `v1` с UUID. В YAML один путь v2.
- Перенос в адресе разобран. `shel- ves` рядом с примером `/shelves` стало `/shelves`. `batch- line` осталось `batch-line`, потому что в имени метода есть слова Batch и Line.
- Перечень «Разрешенные запросы: GET, PUT, DELETE» у судебного дела не породил вызовы. Остался один `POST /court/v1/filings`.
- Абсолютный пример музея не стал вторым сервером. Сервер `{gateway}`, UUID не попал в путь.
- Колонка расположения доехала из хвоста. У счётчика есть `meterPoint` в query и `X-Trace` в header, `readings` — массив.
- Суффикс `.json` снят с пути выпуска: `/press/v1/issues/{issueId}`.
- Вложенный объект доехал из хвоста протокола: `patient.policyNumber`, `protocolStamp`, коды 201, 400 и 422.
- Когда модель отдала метод одним куском длиннее окна, хвост полей сохраняется: печать причала, печать протокола, печать показания.
- Версия с точкой из строки `v 4.2`, `v 2.1`, `v 1.4`, `v 5.0` побеждает строку истории `0.1`.

## Проблемы

### 1. Модель обрывает метод раньше хвоста

Длинный путь включается только если фрагмент длиннее 12000 символов. Модель часто ставит границу на 11500–11900, хвост остаётся за цитатой.

| Документ | Как разрезан | Что потеряно |
| --- | --- | --- |
| Лаборатория | POST оборван на символе 11998, следующий фрагмент начинается на 14050 | Между ними хвост первого метода. Нет `sampleBarcode` и кода 201. Второй метод длинный, `resultStamp` на месте |
| Торги | Голова 11677 и хвост 424 | Хвост подклеился коротким повтором, поля целы. Длинный путь не включился |
| Аптека | То же у обоих методов, 10 вызовов модели | Пути и печати целы. Длинный путь не включился |
| Музей | Голова 11581 и хвост 372 как `/exhibits/{exhibitId}` | Итог один полный путь, печать на месте. Длинный путь не включился |
| Газета | Фрагмент с вызовом — 131 символ, остальной метод операцию не дал | Нет `issueSeal` |

Дыра лаборатории — текст, в котором нет новой строки запроса. Он не входит ни в один фрагмент.

### 2. Целая версия в преамбуле не читается

Шаблон версии требует хотя бы одну точку: `4.2`, но не `6`. Строка истории `0.1` тогда становится версией документа.

Так вышло у аренды (`6`), торгов (`3`), суда (`8`), музея (`2`), газеты (`9`) и протокола (`7`). Версии с точкой записаны верно.

### 3. У длинной сборки пропадает сервер

`compile_operations` не ставит плейсхолдер хоста. Если модель собрала короткий YAML, сервер есть: `{apiUrl}`, `{gateway}`, `{pressHost}`. Если метод пошёл длинным путём, список `servers` пуст: порт, лаборатория, аренда, суд, счётчик, протокол. Путь при этом верный, но без сервера адрес неполный.

### 4. Поля ответа длинной сборки всегда садятся на 200

Компилятор создаёт ответ `200` для полей ответа, а названный код успеха оставляет без схемы.

У порта успех в ТЗ — `201` и `409`. В YAML схема с `berthSeal` висит на `200`, у `201` только подпись. У протокола схема визита висит на `200`, код `201` пустой. Пример тела `422` в схему кода не попал, фраза осталась в описании.

### 5. Единственный код 200 не закрывает каталог

Шаблон `400`, `401`, `404`, `500` не ставится, только если среди кодов есть что-то кроме `200`. Метод, который назвал один `200`, получает весь шаблон.

Так у аренды и у счётчика: в ТЗ только `200`, в YAML ещё четыре кода с пометкой, что это шаблон скилла. У порта есть `409`, шаблон не ставился.

### 6. Поля POST без колонки расположения становятся query

У порта `vesselName` и `imo` лежат в query, хотя это тело создания. У протокола `complaint` тоже в query. У счётчика колонка «Расположение» назвала query и header явно, и сборка этому последовала.

## План

Каждая правка универсальна и не привязана к словам этих десяти ТЗ. Перед ней повторно прогоняются без модели уже успешные артефакты: 13 пробных YAML, ЕНСИ, рецепт, Meowgram, шаблон Habr и `OPENAPI.yaml`. Меняются только те поля, которые правка обязана поменять. Остальные пути, серверы и версии остаются прежними.

1. **Хвост между цитатами возвращать предыдущему методу.** Если между концом фрагмента и началом следующего нет новой строки запроса, этот кусок присоединяется к предыдущему фрагменту до выбора длинного или короткого пути. Через новую строку запроса кусок не переносится: её по-прежнему забирает восстановление пропущенного вызова. Ожидание: лаборатория получает `sampleBarcode`, газета получает `issueSeal`, торги, аптека и музей становятся одним фрагментом длиннее окна и не теряют уже собранные поля.

2. **Читать целую версию рядом с заголовком.** В шаблоне преамбулы допустить число без точки, не ломая `4.2` и `10.5.0`. Если строки `v …` до первой таблицы нет, версия не подменяется: у рецепта остаётся `1.0.0`, у ЕСНСИ остаётся `1`.

3. **Пустой список серверов заполнять плейсхолдером вызовов.** Если `servers` пуст и все адреса документа идут через один плейсхолдер хоста, записать его. Уже заданный сервер не заменять: Meowgram остаётся на своём хосте, ЕСНСИ на своём, короткий путь этих десяти ТЗ не переписывается.

4. **Схему ответа класть на код, который метод назвал успехом.** Если метод назвал `201` или другой `2xx` и не назвал `200`, поля ответа относятся к названному коду. Если назван `200`, схема остаётся на `200`. Лишний пустой `200` рядом с `201` не создаётся.

5. **Шаблон четырёх кодов ставить только когда метод не назвал ни одного кода.** Один названный `200` уже закрывает список. Документ без таблицы кодов по-прежнему получает шаблон, как сейчас.

6. **В скилле уточнить таблицу запроса без колонки расположения.** У `POST`, `PUT` и `PATCH` такие поля — тело. `query`, `path` и `header` берутся только из колонки, которая это расположение назвала. Явные query проб и заголовок `X-Trace` остаются на своих местах.
