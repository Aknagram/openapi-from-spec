# OpenAPI 3.0.3 для задачи openapi

Документ самодостаточен. Сеть для этих правил не нужна. Модель пишет YAML одного фрагмента. Код потом сшивает `paths` и `components` нескольких фрагментов.

## Корень

- `openapi`: строка `3.0.3`
- `info.title` — заголовок документа или первый содержательный заголовок фрагмента. `info.version` — ячейка версии из таблицы истории, строкой в кавычках. `API` и `1.0.0` не оставляй, когда во фрагменте названы другие значения. Если версии в фрагменте нет, версия — `"1.0.0"`
- `paths`: объект. Ключ — путь, значение — методы `get`, `post`, `put`, `patch`, `delete`, `head`, `options`

`servers` пиши, только если адрес или плейсхолдер есть во фрагменте. Схему безопасности не выдумывай.

Запись `{base_url}/claim/individual` даёт путь `/claim/individual` и сервер:

```yaml
servers:
  - url: "{base_url}"
    variables:
      base_url:
        default: /
```

Имя плейсхолдера бери из фигурных скобок фрагмента. Готовый путь из ТЗ не дополняй префиксом `/api/v1`. Если во фрагменте есть полный адрес метода, путь и сервер берутся из него: короткий заголовок с тем же методом его не заменяет. Префикс сервера в пути не повторяй: если сервер уже кончается на `/api/v1`, пример `POST /api/v1/users` даёт путь `/users`. Число в конце примера (`PUT /transactions/1`) — path-параметр `{id}`, а не часть пути без параметра. Если во фрагменте только имя вроде `accountBalances` и нет пути, путь — kebab-case во множественном числе. Версию в начало пути ставь только если она названа во фрагменте: `/api/v1/account-balances`. Если версии нет, префикс не выдумывай.

## Операция

Нужны `operationId`, `summary`, `tags` и `responses`. `summary` — фраза из фрагмента. `tags` — один домен в PascalCase по имени ресурса: `Orders`. Тег — слово, которое есть во фрагменте. Добавляй `description`, `parameters`, `requestBody`, только если они есть во фрагменте.

`operationId` — глагол и имя ресурса в camelCase: `getAccountBalances`. Имя path-параметра в него не входит: `GET /recipes/{recipeId}` даёт `getRecipes`, не `getRecipesRecipeId`. Во всём документе `operationId` уникален. Если метод выведен из смысла фрагмента, а не из глагола HTTP, добавь `x-method-origin: inferred`.

## Параметр и схема

`name`, `in` (`query`, `path`, `header`, `cookie`), `schema`, `description`. Параметр пути всегда `required: true`.

`type` — только `string`, `number`, `integer`, `boolean`, `array` или `object`. Слово из ТЗ в `type` не пиши.

| Как в ТЗ | OpenAPI |
| --- | --- |
| String, Text, Строка | string |
| String (url), string (url) | string, format uri |
| String(12) | string и `maxLength: 12` |
| UUID | string, format uuid |
| Date, Дата | string, format date |
| DateTime, Date-Time, Дата и время, string (timestamp) | string, format date-time |
| Boolean, Bool, Логический, Булево | boolean |
| Integer, Int, Целое | integer |
| Long, Int64 | integer, format int64 |
| Number, Decimal, Число | number |
| Double | number, format double |
| Float | number, format float |
| Object, Объект | object |
| Array, List, Set, Массив, Список | array |
| File, Binary, Файл | string, format binary |

У каждого `array` есть `items`. Если ячейка типа говорит только `array`, а в примере у этого поля читаются строки, например `["Салаты", "Обед"]`, у `items` тип `string`. Другие свойства из обрезанного примера не добавляй. Вложенные строки `└─` — свойства объекта или элемента массива.

Число длины у строки — `maxLength`. У целого и числа — `x-tz-max-length`, не `maxLength`. У списка строк длина относится к `items`, не к самому массиву. Запись вида `String(12)` даёт `maxLength: 12`, даже если отдельной длины нет.

Обязательность решает фрагмент своей пометкой или фразой про это имя. Пометка «обязательно» даёт `required: true`, пометка «необязательно» — `required: false`. Конкретные буквы и слова заранее не заданы: прочитай пометку, которая стоит у этого имени. Пустая пометка — ключ `required` не ставь и поле не включай в массив `required` схемы. Если в ячейке перечислены глаголы, поле обязательно в запросе этих методов и не входит в `required` схемы ответа.

У схемы тела и вложенного объекта `required` — массив имён, которые фрагмент счёл обязательными. Остальные в этот массив не входят. Пустая пометка относится к самой строке, а не к детям: имя родителя не попадает в `required`, даже когда каждое вложенное поле обязательно.

Повтор ключа в строке метода (`accounts=a&accounts=b`) для массива: `style: form` и `explode: true`.

Объект с несколькими полями клади в `components/schemas` и ссылайся через `$ref`. Имя схемы — PascalCase: `UserResponse`, `CreateUserRequest`. Одну и ту же схему второй раз inline не копируй. В 3.0.3 рядом с `$ref` не ставь другие поля.

`example` у поля, параметра или ответа пиши только если этот JSON есть во фрагменте и разбирается. Пример, которого в ТЗ нет, не сочиняй. Таблица полей важнее примера, когда пример не разбирается: такой пример не задаёт свойства. Поля ответа в этом случае бери из таблицы, а не из примера.

Если пример разбирается и значение поля — массив, у свойства `type: array`. Имя свойства — ключ примера. Тип элемента бери из ячейки типа: именованная структура даёт `$ref` на схему элемента. Если ячейка говорит о строке, а массив в примере пустой, у `items` тип `string`. Этот пример в YAML копируй. Поле из таблицы, которое есть в целом JSON-примере, остаётся в схеме. Поле, которое есть только в целом примере, тоже остаётся. Тип бери из значения и из таблицы типов выше. `null` рядом с названным типом даёт `nullable: true`. Если таблица уже задала другой тип, формат не ставь только из-за похожей строки. Если ключ примера и имя в таблице — одно поле в разном числе, пояснение таблицы пиши у ключа примера.

Если у входа перечислено несколько форматов и один `format` покрывает не все, `format` не ставь и перечисли форматы в `description`. Поле, которое фрагмент относит к серверу, а не к данным клиента, в тело запроса не включай. Объяснение ошибки поставь у кода, который фрагмент назвал для этого правила. Имя, которое фрагмент относит к заголовкам запроса, — параметр `in: header`. Если фрагмент говорит, что у кода нет тела, `content` нет. `summary` — фраза фрагмента о вызове, не название раздела. Строка вызова с полным адресом — такой же вызов, как строка с путём.

## Ответ

У каждого элемента `responses` есть `description`. Для кода, который фрагмент относит к вызову, это объяснение фрагмента, не заголовок раздела. Если пример этого кода содержит текст сообщения и он не спорит с объяснением, бери текст сообщения. Если пример спорит с объяснением, в `description` пиши объяснение, а сам пример в YAML не копируй. Не подставляй сам код вместо объяснения. Без `description` проверка 3.0.3 не проходит.

Если таблицы ответа нет, всё равно запиши успешный код и без `content`, когда тела нет. Этот код — оболочка операции, а не выдуманные поля. Если у успеха нет своей фразы, в `description` поставь `summary` операции, не заголовок раздела. Тело ответа добавляй только по таблице или примеру фрагмента.

Код, названный во фрагменте, запиши с его объяснением, в любой записи: число, строка статуса, подпись. Текст сообщения бери из примера этого кода. Пример относится только к своему коду: тело одного кода не копируй в другой. Если фрагмент говорит, что тела нет, `content` у кода нет. Набор 400, 401, 404, 500 не добавляй целиком: код из этого набора, которого во фрагменте нет, не записывай. Код, который фрагмент назвал без своего тела, можно оставить общим шаблоном, без тела. Если фрагмент сам задаёт список кодов сервиса, список закрытый: код из списка запиши с его объяснением, а шаблон для кода вне списка не добавляй.

```yaml
components:
  responses:
    BadRequest:
      description: Некорректный запрос
      x-origin: skill-template
    Unauthorized:
      description: Требуется аутентификация
      x-origin: skill-template
    NotFound:
      description: Ресурс не найден
      x-origin: skill-template
    InternalError:
      description: Внутренняя ошибка сервиса
      x-origin: skill-template
```

В операции ссылка без соседних полей:

```yaml
"400":
  $ref: "#/components/responses/BadRequest"
```

Фразу из ТЗ шаблоном не заменяй. Если 400 во фрагменте назван, у этого кода `description` из фрагмента, а не `BadRequest`. Компонент, на который ведёт `$ref`, объяви в `components/responses` того же документа.

## Если проверка вернула oneOf

Текст ошибки не называет поле. Сначала проверь два места: у ответа нет `description`; в `type` осталось слово ТЗ вроде `UUID`, `Decimal`, `Float` или `File`.

## Чего не добавлять

Не добавляй поля, заголовки авторизации и коды ответов вне набора 400, 401, 404, 500, если их нет во фрагменте. Шаблон этого набора не содержит свойств из ТЗ. Не используй возможности 3.1: массив в поле `type`, `webhooks`, поля рядом с `$ref`.
